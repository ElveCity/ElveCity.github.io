# Operating System_21
***
   
## SLC, MLC, TLC
   
플래시 칩의 트랜지스터 하나에 몇 비트를 저장하느냐에 따른 분류.
   
SLC(Single-Level Cell)은 1비트, MLC(Multi-Level Cell)는 2비트, 
TLC(Triple-Level Cell)은 3비트를 저장함.
   
SLC가 성능가 내구성이 가장 높지만 가격이 비쌈.
   
## 플래시 계층 구조 (Banks/Planes, Blocks, Pages)
   
플래시 칩은 여러 개의 뱅크(Bank) 또는 플레인(Plane)으로 구성됨.
   
각 뱅크는 블록(Block, 보통 128KB~256KB)단위로 나뉘며, 블록은 다시 더 
작은 페이지(Page, 보통 수 KB)단위로 나뉨.
   
## 쓰기 전 삭제 (Erase-before-write)
   
플래시 메모리의 가장 큰 특징이자 제약 사항.
   
페이지 단위로 읽고 쓸 수 있지만, 이미 데이터가 쓰여진 페이지에 다시 
쓰기(프로그램)를 하려면 해당 페이지가 포함된 블록 전체를 먼저 삭제해야함. 
   
## 페이지 상태 전환
   
페이지는 처음에 INVALID 상태에서 시작해서 블록 삭제 시 ERASED 상태가 되어 
프로그래밍이 가능해짐.
   
데이터를 기록하면 VALID 상태가 되며, 이후 내용을 바꾸려면 다시 블록 삭제 과정을 거쳐야 함.
   
## FTL (Flash Translation Layer, 플래시 변환 계층)
   
SSD 내부의 컨트롤러에서 실행되는 소프트웨어.
   
OS가 사용하는 논리 블록 주소(LBA)를 플래시 메모리의 실제 물리 페이지 주소로 
매핑해서, SSD가 일반 하드디스크처럼 동작하도록 속이는 역할 수행.
   
## 로그 구조 FTL (Log-structed FTL)
   
현대적인 FTL 방식으로, 데이터를 덮어 쓰는 대신 빈 공간에 계속 덧붙여 쓰는(Logging) 방식.
   
이를 통해서 삭제/프로그램 사이클을 최소화하고 성능을 높임.

## 가비지 컬렉션 (Garbage Collection)
   
로그 구조 방식에서 발생하는 유효하지 않은(Dead) 페이지들을 정리하는 과정.
   
유효한 데이터만 새 블록으로 옮기고 기존 블록을 삭제해서 빈 공간 확보.
   
## 쓰기 증폭 (Write Amplification)
   
사용자가 요청한 데이터 양보다 실제 플래시 칩에 기록되는 데이터 양이 
가비지 컬렉션 등의 내부 작업으로 인해 더 많아지는 현상.
   
## 웨어 레벨링 (Wear Leveling)
   
플래시 블록은 삭제 횟수에 한계가 있어서 특정 블록만 집중적으로 사용하면 
수명이 다하게 됨.
   
FTL은 모든 블록에 쓰기 작업이 고르게 분산되도록 관리해서 SSD의 전체 수명을 연장함.

## Trim 명령
   
운영체제가 특정 블록의 데이터가 더 이상 필요 없음을 SSD에 알려주는 인터페이스.
   
이를 통해서 SSD는 가비지 컬렉션을 더 효율적으로 수행 가능.
   
## 하이브리드 매핑 (Hybrid Mapping)
   
메모리 효율을 위해 대부분은 블록 단위로 매핑(Block mapping)하고 
빈번하게 업데이트되는 일부 영역만 페이지 단위로 매핑(Page mapping)하는 절충안
