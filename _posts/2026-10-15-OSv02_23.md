# Operating System_23
***
   
## 시스템 버스 계층 구조 (Hierarchical Architecture)
   
성능, 비용의 균형을 맞추려고 계층적 버스 구조를 가짐.

### 메모리 버스
   
CPU와 메모리를 연결하는 가장 빠른 전용 버스
   
### 일반 I/O 버스 (ex. PCI, PCIe)
   
고성능 장치(그래픽 카드 등)가 연결됨.

### 주변 장치 버스 (ex. SCSI, SATA, USB)
   
상대적으로 느린 장치(디스크, 키보드, 마우스)를 연결하며, 많은 수의 장치 수용 가능.

## 표준 장치 구조 (Canonical Device)
   
장치는 크게 두 부분으로 나뉨.

### 인터페이스
   
시스템 소프트웨어가 제어할 수 있도록 노출된 레지스터(Status, Command, Data)세트.
   
### 내부 구조
   
장치의 기능을 실제로 구현하는 마이크로컨트롤러, 메모리, 펌웨어 등을 포함.
   
## 상호작용 프로토콜
   
### 폴링 (Polling) 
   
OS가 장치의 상태 레지스터를 반복적으로 읽어 준비 상태를 확인하는 방식.
   
구현은 단순하나 대기 시간 동안 CPU를 점유해서 낭비가 큼.
   
### 인터럽트 (Interrupt)
   
OS가 요청을 보낸 후 CPU를 다른 프로세스에 넘기고, 장치가 작업을 마치면 신호를 
보내 OS를 깨우는 방식.
   
CPU와 I/O 작업의 중첩(Overlap)을 가능하게 하여 효율을 높임.
   
### PIO (Programmed I/O)
   
CPU가 직접 데이터를 장치 레지스터로 옮기는 방식.
   
데이터 양이 많을 경우 CPU에 과도한 부담을 줌.
   
## DMA (Direct Memory Access)
   
CPU의 개입 없이 장치와 메인 메모리 간 데이터를 직접 전송하는 전용 엔진.
   
데이터 전송 작업을 오프로드(Offload)해서 CPU가 다른 일을 할 수 있게 도움.
   
## 장치 통신 방법
   
### 명시적 I/O 명령어
   
x86의 in, out과 같이 특정 포트를 통해 장치와 통신하는 전용 명령어.
   
### 메모리 맵 I/O (Memory-mapped I/O)
   
장치의 레지스터를 메모리 주소 공간의 일부로 매핑해서 일반적인 load / store 명령어로 접근하는 방식.
   
## 장치 드라이버 (Device Driver)
   
특정 장치의 세부적인 제어 방법을 알고 있는 운영체제 내의 소프트웨어 계층.
   
장치마다 다른 하드웨어 인터페이스를 추상화해서 상위 계층(ex. file system)이 
장치 종류에 상관없이 일관된 방식으로 요청을 보낼 수 있게 함.
   
## 라이브락 (Livelock)
   
네트워크 패킷처럼 인터럽트가 너무 빈번하게 발생해서, 시스템이 인터럽트 처리만 
하느라고 실제 사용자 프로세스를 실행하지 못하고 멈추는 현상.
   
이를 방지하기 위해 일시적으로 폴링으로 전환하거나 합치기(Coalescing)기법을 사용.
