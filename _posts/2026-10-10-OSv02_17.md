# Operating System_17
***
   
## Crash-consistency Problem (충돌 일관성 문제)
   
파일 시스템 업데이트 중 시스템이 중단되어 디스크 상의 데이터 구조가 일부만 업데이트 될 때 
발생하는 비일관성문제. 
   
원자적(Atomic) 업데이트가 불가능한 디스크 하드웨어의 특성 때문에 발생.
   
## fsck (File System Checker)
   
비일관성 해결 도구. 시스템 충돌 후 부팅 시 전체 디스크를 스캔해서 메타데이터 오류(잘못된 링크 카운트, 중복 포인터 등)를 찾아 
수정함. 디스크 용량이 커질수록 스캔 시간이 매우 오래 걸린다는 점이 단점.
   
## Journaling (저널링 / Write-ahead Logging)
   
데이터를 실제 위치에 쓰기 전에 변경사항을 저널(Journal)또는 로그(Log)라는 전용 공간에 먼저 기록하는 기법. 
충돌 시 저널만 확인하면 되므로 복구 속도가 많이 빠름.
   
## Transaction (트랜잭션)
   
저널링에서 하나의 논리적 단위로 묶인 업데이트 세트. 시작을 알리는 TxB(Transaction Begin)블록과 
끝을 알리는 TxE(Transaction End) 블록 사이에 실제 변경된 블록 내용이 포함됨.
   
## Physical Logging (물리적 로깅)
   
업데이트될 블록의 전체 내용을 저널에 그대로 복사하여 기록하는 방식.
   
## Checkpointing (체크포인팅)
   
저널에 안전하게 기록(커밋)된 트랜잭션의 변경 내용을 실제 파일 시스템 구조(최종 위치)에 
반영하는 작업.
   
## Circular Log (순환 로그)
   
저널 공간을 효율적으로 사용하기 위해, 끝까지 기록한 후 다시 처음으로 돌아가 공간을 재사용하는 구조.
   
## Journal Superblock (저널 슈퍼블록)
   
체크포인트가 완료되지 않은 가장 오래된 트랜잭션과 최신 트랜잭션의 위치 등 저널의 상태정보를 담고 있는 특수 블록.
   
## Data Journaling (데이터 저널링)
   
파일 시스템의 메타데이터뿐만 아니라 사용자의 실제 데이터까지 모두 저널에 기록하는 방식.
   
가장 안전하지만 모든 데이터를 두 번 써야 하므로 성능 부하가 큰 편.
   
## Metadata Journaling (메타데이터 저널링 / Ordered Journaling)
   
데이터는 직접 파일 시스템에 쓰고, 메타데이터만 저널링하는 방식.
   
이때 데이터를 먼저 쓰고 저널링하는 순서를 강제해서 데이터 무결성을 보장함.
   
## Transaction Checksum(트랜잭션 체크섬)
   
트랜잭션 블록들의 요약 값을 TxB나 TxE에 포함시키는 최적화 기법.
   
이를 통해 TxE 블록 쓰기를 완료할 때까지 기다리지 않고 모든 블록을 한꺼번에 보낼 수 있어 성능이 향상됨.
   
## Soft Updates
   
복잡하고 정교한 쓰기 순서 제어를 통해 저널 없이도 파일 시스템 일관성을 유지하는 기법.
   
## Backpointer-based Consistency (BBC)
   
각 블록에 자신이 속한 아이노드 정보를 역방향 포인터로 두어, 일관성을 사후에 검증할 수 있게 하는 기법
