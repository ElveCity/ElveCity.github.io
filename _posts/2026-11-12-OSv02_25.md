# Operating System_25
***
   
## NFS(Network File System)
   
분산 파일 시스템.
   
클라이언트가 원격 서버의 파일을 자신의 로컬 디스크에 있는 것처럼 
투명하게(Transparent) 접근 가능케함.
   
## Stateless Protocol(무상태 프로토콜)
   
NFS의 핵심 설계 원칙.
   
서버는 클라이언트가 어떤 파일을 열었는지, 현재 파일 포인터 위치가 어디인지 등의 
상태 정보를 일체 유지하지 않음. 
   
이 방식은 서버가 충돌 후 재부팅돼도 이전 상태를 복구할 필요 없이 즉시 요청을 
처리할 수 있기에 빠른 장애복구를 가능케함.
   
## File Handle(파일 핸들)
   
파일이나 디렉터리를 고유하게 식별하기 위해 사용하는 식별자.
   
볼륨 식별자, 아이노드 번호, 세대 번호(Generation number)를 포함하며, 
클라이언트는 파일 경로 대신 이 핸들을 써서 서버에 요청을 보냄.
   
## Indempotency(멱등성)
   
동일한 요청을 여러 번 수행해도 결과가 한 번 수행한 것과 같은 성질을 의미.
   
NFS의 많은 연산(READ, WRITE, LOOKUP 등)은 멱등성을 가지도록 설계되어, 
네트워크 패킷 손실 시 클라이언트가 단순히 요청을 재시도(Retry)하는 것 만으로도 
오류를 해결할 수 있음.
   
## Cache Consistency Problem(캐시 일관성 문제)
   
성능을 위해 클라이언트가 데이터를 캐싱하면서 발생하는 문제.
   
한 클라이언트가 수정 중인 내용이 다른 클라이언트에게 보이지 않는 업데이트 가시성 문제와, 
서버에 새 버전이 있음에도 클라이언트가 옛날 데이터를 읽는 오래된 캐시 문제가 있음.
   
## Flush-on-close(Close-to-open) Consistency
   
캐시 문제를 해결하기 위한 NFS의 정책.
   
애플리케이션이 파일을 닫을(close()) 때 모든 수정된 내용을 강제로 서버에 전송(Flosh)하며, 
이후 다른 클라이언트가 파일을 열 때 최신 데이터를 보장받도록 함.
   
## Attribute Cache(속성 캐시)
   
파일의 메타데이터(크기, 수정 시간 등)를 일정 시간(보통 수 초)동안 캐싱하여 
서버로 가는 GETATTR 요청의 수를 줄이는 기법.
   
## VFS/Vnode Interface
   
NFS도입에서 운영체제에 추가된 계층.
   
여러 종류의 파일 시스템(로컬, 분산 등)을 일관된 방식으로 처리할 수 있도록 추상화된 
인터페이스를 제공.
