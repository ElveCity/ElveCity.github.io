# Operating System_15
***
   
## Data Integrity / Data Protection (데이터 무결성/데이터 보호)
   
저장 시스템에 기록한 데이터가 나중에 읽었을 때도 기록 시점의 데이터와 정확히 
일치함을 보장하는 기술과 원리.
   
## Latent Sector Error (LSE, 잠재적 섹터 오류)
   
디스크 헤드가 표면에 닿는 헤드 크래시나 우주선(Cosmic rays) 등의 영향으로 특정 섹터가 
물리적으로 손상되어 읽을 수 없게 되는 오류. 
   
디스크가 읽기 요청 시 에러를 반환하기에 시스템이 즉시 인지 가능.
   
## Block Corruption (블록 손상, Silent Corruption)
   
디스크가 읽기 요청에 대해 에러를 내지 않고 잘못된 데이터를 반환하는 오류. 
   
감지가 어려움, 무결성 보호의 핵심 과제
   
## Fail-stop model vs Fail-partial model
   
- Fail stop
   
디스크가 아예 통째로 고장나거나 아니면 완벽히 작동한다는 과거의 단순모델.
   
- Fail-partial
   
디스크 대부분은 작동하지만 일부 블록만 접근 불가(LSE)하거나 손상(Corruption)될 수 있다는 
현대적 실패 모델.
   
## Checksum (체크섬)
   
데이터의 요약 값. 데이터와 함 께 저장했다가 읽을 때 다시 계산해서 데이터 손상을 확인하는 도구.
   
1) XOR-based
   
각 데이터 단위를 XOR 연산해서 합을 구하는 방식, 두 비트가 동시에 변하면 감지하지 못하는 한계 존재.
   
2) Fletcher Checksum
   
덧셈을 활용해서 위치 변화(Shift)까지 감지할 수 있도록 설계된 좀 더 강력한 체크섬 방식.
   
3) Cyclic Redundancy Check (CRC)
   
데이터를 큰 이진수로 보고 특정 값으로 나눈 나머지를 사용하는 방식.
   
네트워크와 저장 장치에서 널리 쓰이는 매우 강력한 기법.
   
## Collision (충돌)
   
서로 다른 데이터 블록이 우연히 같은 체크섬 값을 가지게 되어 데이터 손상을 감지하지 못하는 상황.
   
## Misdirected Write (오지시 쓰기)
   
디스크가 데이터를 써야 할 올바른 위치가 아닌 다른 위치에 쓰는 오류.
   
방지를 위해 체크섬에 디스크 번호, 블록 주소를 포함하여 저장하기도 함.
   
## Lost Write (분실된 쓰기)
   
디스크가 쓰기 완료를 보고했지만 실제로는 데이터가 영속적으로 저장되지 않아 
옛날 데이터가 그대로 남는 현상. 
   
ZFS같은 시스템은 아이노드 내부에 체크섬을 둬서 이를 감지함.
   
## Disk Scrubbing (디스크 스크러빙)
   
평소에 잘 읽지 않는 데이터가 서서히 손상되는 비트 부패(Bit rot)를 방지하기 위해, 
주기적으로 시스템의 모든 블록을 읽어 체크섬을 검사하고 오류를 복구하는 작업.
