# Operating System_14
***
   
## Andrew File System (AFS)
   
분산 파일 시스템. 서버 한 대가 가능한 많은 클라이언트를 지원할 수 있도록 하는 
확장성을 최우선 목표로 설계함.
   
## Whole-file caching (전체 파일 캐싱)
   
클라이언트가 파일을 열 때(open()) 서버로부터 파일 전체를 로컬 디스크로 가져와 저장하는 방식. 
   
이후 읽기/쓰기는 로컬에서 수행되기에 네트워크 트래픽이 줄고 속도가 빠름.
   
## Callback (콜백)
   
서버가 클라이언트에게 파일이 변경되면 알려주겠다라고 약속하는 메커니즘. 
   
이를 통해 클라이언트는 서버에 매번 파일 유효성을 묻지 않고도 자신의 캐시가 유효하다고 
가정할 수 있어서 서버 부하가 많이 줄어듬.
   
## Cache Consistency (캐시 일관성)
   
여러 클라이언트가 동일한 파일을 사용할 때 데이터의 정확성을 유지하는 원리.
   
AFS는 파일을 닫을 때(close())만 서버로 변경 내용을 전송하는 Flush-on-close방식을 씀. 
   
서버는 콜백을 통해 다른 클라이언트의 캐시를 무효화함.
   
## Update Visibility (업데이트 가시성)
   
한 클라이언트가 수정한 내용이 언제 다른 클라이언트에게 보이게 되는지에 대한 문제. 
   
AFS에서는 파일을 닫은 후 다른 클라이언트가 새로 파일을 열 때 최신 내용을 보장함.
   
## Cache Staleness (캐시 신선도)
   
서버에 새 버전이 있음에도 클라이언트가 이전의 낡은 데이터를 계속 사용하는 현상. 
   
콜백이 이 문제를 해결하려고 들어간 것.
   
## TestAuth (인증 테스트)
   
클라이언트가 부팅 후나 특정 상황에서 자신의 캐시가 여전히 유효한지 서버에 
명시적으로 확인 요청을 보내는 프로토콜 메세지.
   
## Last writer wins (최종 기록자 승리)
   
여러 클라이언트가 동시에 같은 파일을 수정하고 닫을 때, 가장 마지막에 파일을 닫은 
클라이언트의 내용이 최종적으로 서버에 남게 되는 정책.
