# Operating System_19
***
   
## Block (블록)
   
디스크를 나누는 고정된 크기의 단위.
   
VSFS(Very Simple File System)에서는 일반적으로 4KB 크기를 사용하며, 
전체 디스크는 0부터 N-1까지의 블록 배열로 관리됨.
   
## Data Region (데이터 영역)
   
디스크 상에서 실제 사용자 데이터가 저장되는 영역.
   
일반적으로 파일 시스템 공간의 대부분을 차지함.
   
## Inode (Index Node / 아이노드)
   
파일의 메타데이터를 담고 있는 핵심 구조체.
   
파일 크기, 소유자, 권한, 수정 시간 및 해당 파일의 데이터 블록이 디스크 어디에 
위치하는지에 대한 포인터 정보를 포함.
   
## Inode Table (아이노드 테이블)
   
디스크 상의 아이노드(inode)들이 배열 형태로 저장되는 영역.
   
## I-number (아이노드 번호)
   
각 아이노드에 부여된 고유 번호. 파일 시스템은 이 번호를 인덱스 삼아 
아이노드 테이블에서 특정 아이노드의 물리적 위치를 즉시 계산해서 읽어올 수 있음.
   
## Bitmaps (비트맵)
   
아이노드와 데이터 블록의 사용 여부를 추적하기 위한 단순한 데이터 구조.
   
아이노드 비트맵과 데이터 비트맵이 있으며, 각 비트가 0이면 빈 상태(free), 
1이면 사용 중(in-use)임을 나타냄.
   
## Superblock (슈퍼블록)
   
특정 파일 시스템의 전체적인 정보를 담고 있는 특수 블록.
   
아이노드와 데이터 블록의 총 개수, 아이노드 테이블의 시작 위치, 파일 시스템 유형을 
식별하는 매직 넘버(magic number)등을 포함.
   
## Multi-level Index (다단계 인덱스)
   
큰 용량의 파일을 지원하기 위해 아이노드 내부에 사용하는 포인터 체계.
   
실제 데이터를 가리키는 직접 포인터(direct pointer)외에, 포인터들의 블록을 가리키는 
간접 포인터(indirect pointer), 이중/삼중 간접 포인터를 사용해서 파일 크기를 확장함.
   
## Free Space Management (빈 공간 관리)
   
새로운 파일 생성 시 비트맵을 검색하여 비어 있는 아이노드나 데이터 블록을 
찾아 할당하는 과정. 
   
성능 향상을 위해 연속된 블록을 할당하는 사전 할당(pre-allocation)정책을 쓰기도 함.
   
## I/O Costs (I/O 비용)
   
파일 생성이나 쓰기 작업은 보기보다 많은 디스크 I/O를 발생시킴.
   
파일을 생성하고 데이터를 쓰는 과정에서 비트맵 읽기/쓰기, 
아이노드 읽기/쓰기, 디렉터리 업데이트, 실제 데이터 쓰기 등 여러 단계의 작업이 수반됨.

## Direct Organization (디렉터리 구성)
   
디렉터리 또한 특수한 형태의 파일로 취급됨.
   
그 데이터 블록에는 해당 디렉터리에 포함된 (이름, 아이노드 번호)쌍의 리스트가 저장되어 있음.
