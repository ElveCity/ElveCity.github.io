# Operating System_20
***
   
## File (파일)
   
읽거나 쓸 수 있는 선형적인 바이트 배열.
   
각 파일은 시스템 내부에서 관리되는 아이노드 번호(inode number or i-number)라는 저수준 이름을 가짐.
      
## Directory (디렉터리)
   
파일과 마찬가지로 아이노드 번호를 가지지만, 그 내용이 (사용자가 읽을 수 있는 이름, 아이노드 번호) 쌍의 
리스트로 구성된 특수한 파일.
   
디렉터리 안에 다른 디렉터리를 포함함으로써 전체 시스템은 디렉터리 계층 구조(Directory Tree)를 형성.
   
## File Descriptor (파일 서술자)
   
open() 시스템 호출이 반환하는 정수 값으로, 프로세스마다 비공개적으로 관리됨.
   
이는 해당 파일에 대해 특정 작업을 수행할 수 있는 권한을 나타내는 기능(Capability)의 역할 수행.
   
## Iseek()
   
파일 내에서 다음 읽기 또는 쓰기가 수행될 위치인 현재 오프셋(Current Offset)을 
명시적으로 변경하는 호출.
   
중요한 점은 이 호출 자체만으로는 디스크의 헤드를 움직이는 물리적 디스크 탐색(Disk Seek)을 
수행하지 않으며, 단지 운영체제 메모리 내의 변수만 업데이트 한다는 것.
   
## fsync()
   
응용 프로그램이 write()를 호출하더라도 운영체제는 성능을 위해 데이터를 즉시 디스크에 쓰지 않고 버퍼링함.
   
fsync()는 지정된 파일 서술자의 모든 더티(dirty)데이터를 즉시 영속적인 저장 장치에 
강제로 기록하도록 명령함.
   
## rename()
   
파일의 이름을 변경하는 시스템 호출.
   
파일 업데이트 시 임시 파일을 생성한 후 원래 이름으로 덮어 쓰는방식임.
   
원자적인 업데이트 구현 시 자주 사용함.
   
## Metadata (메타데이터)
   
파일의 실제 내용(데이터)를 제외한 모든 정보를 의미.
   
파일 크기, 아이노드 번호, 소유권, 권한, 수정 시간 등이 포함.
   
stat() 또는 fstat()호출을 통해 이를 확인 가능.
   
## Hard Link (하드 링크)
   
기존 파일의 아이노드 번호에 새로운 이름을 연결하는 방식.
   
파일 시스템은 이름만 다를 뿐 동일한 아이노드를 가리키는 이들을 구분하지 않기에 
파일은 모든 링크가 끊어져 참조 횟수(Link count)가 0이 될때만 실제로 삭제됨.
   
## Symbolic Link (심볼릭 링크 / 소프트 링크)
   
원본 파일의 경로명을 데이터로 담고 있는 특수한 타입의 파일.
   
원본 파일이 삭제되면 링크가 쓸모없어지는 댕글링 래퍼런스(Dangling reference)문제 발생 가능.
   
## Access Control List(ACL)
   
권한 비트보다 더 세밀한 제어가 필요한 경우 사용하는 방식.
   
특정 자원에 접근할 수 있는 사용자들의 목록을 구체적으로 명시함.
   
## Mount (마운트)
   
서로 다른 장치에 존재하는 개별 파일 시스템들을 하나의 통합된 디렉터리 트리로 합치는 과정.
   
mount 명령을 통해 특정 디렉터리(마운트 지점)에 새로운 파일 시스템을 붙여 
사용자에게 일관된 네임스페이스를 제공함.
